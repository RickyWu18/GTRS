# tools/ — 離線工具鏈

統一以 Python 撰寫。**不屬於網站執行路徑**——前端仍為純靜態，不需任何建置步驟即可執行。

計畫書 4.3 的「純前端」限制其目的是保障貢獻者的工作流程（新增內容不需安裝工具、
commit 即生效），不禁止 repo 中存在由離線腳本產生的檔案。`generated/` 下的產物
由 CI 在 push 後重建，貢獻者無須感知其存在。

## 管線選型（W0.7 已定案，2026-09-24）

計畫書 7.2 建議的本地方案（Surya、Texify、本地 VLM）**假設有可用 GPU**，本機無 GPU，
故該節的候選工具表不適用。W0.7 實測後定案為**不採用版面偵測模型**：

| 工作 | 由誰 | 理由 |
|---|---|---|
| 版面切割、bbox | 古典 CV（numpy 投影剖面，`layout.py`） | 確定性、可重跑、無 GPU；且不會如模型般「補全」不存在的區塊 |
| 區塊內容轉錄 | VLM | 來源無文字層，別無選擇 |
| 逐字核對 → `reviewed` | 人眼 | 不可外包 |

完整依據見 `docs/W0.6-W0.7-測試結果.md`。

**轉錄用的裁切一律不得貼齊內容邊界**，bbox 各邊須留 0.005–0.01 邊距。W0.7 實測到
`WAITIC` 被讀成 `ALTIC`——首字母遭截斷後，剩下的部分仍是一個看起來合理的字串，
沒有任何跡象顯示發生了截斷。

## 硬性規則

**一切機器產出一律標記 `status: draft`**，無論來自 OCR、公式辨識或視覺語言模型。
唯有經人眼逐字對照掃描原文核對後方可升級（計畫書 9.5）。

VLM 會對辨識不清的符號進行「補全」，產生語法正確、外觀合理但內容錯誤的輸出。
由於本專案排除數值驗證，此類錯誤缺乏自動偵測手段。
